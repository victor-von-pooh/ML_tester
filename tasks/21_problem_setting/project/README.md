# 総菜の作る量

ML-Quest の問題の設定 (`problem.yaml`) から書き出した, ML-Found のプロジェクトの骨組み.

## 課題から行動まで

- 店長の課題: 総菜の廃棄が多く, 夕方には品切れも出る
- 今のやり方: 前の週の同じ曜日と同じ数を作る
- 解けたと言える指標: 廃棄と欠品の損 (円 / 月. 今 1,200,000. 目指す 960,000. 小さいほど良い)
- 機械学習で予測すること: 翌日の品ごとの売れる数 (時系列の予測. 目的の列 sales)
- 店長が前の日の 17 時に品ごとの作る量を決める
- 意思決定: 量を決める (under_cost 200, over_cost 150)
- 成功の基準: 廃棄と欠品の損が今のやり方より 2 割少ない

## 次にすること

学習する環境には ML-EDA, ML-ModelControl, ML-Found, ML-Inference を入れる.

1. **データの分析** (ML-Fathom. コードなら ML-EDA の `export_dataset`): データを読み, 次の値でレシピを作り, このディレクトリの `outputs/dataset` に書き出す. 検証用の分割は必ず作る
    - 目的の列: `sales`, タスク: `forecasting`, 分割: 時刻の順 (先の期間を検証用とテスト用に)
    - 時刻の列: `date` (読み込みで日時の列に指定する. 系列を分ける列が複数あると推定できないため), 系列を分ける列: `store`, `item`
    - 過去の値の列は 2 期前より古い値だけで作る (ずらし幅は 2 以上. 移動平均も, 決める時点で分からない期を含めない). 決める時点で分からない値で学習すると, 学習のときだけ当たる
    - 学習に使ってよい列 (予測の時点で分かる列): `store`, `item`, `temperature_forecast`, `promo`
    - 学習に使わない列 (予測の時点で分からない列と, 使ってはいけない列): `customers`
2. **モデルの作成** (ML-CreateArchitecture): 入力 1 つと出力 1 つのモデルを組み, `models/model.yaml` に置く. 入力の大きさは書き出したデータセットの学習に使う列の数 (`dataset.yaml` の features. ワンホットや過去の値の列で元の列より増える), 出力の大きさは 1. 回帰の目的の値は train.py が標準化する
3. **学習** (ML-Found, ML-Dashboard): `python train.py` (`python train.py trainer.epochs=10` のように「項目=値」で上書きできる). 結果は `outputs/<実験の名前>/<日付>/<時刻>/` に残る. 検証用の `valid/mae` が最も良いモデルを選ぶ
4. **推論** (ML-Provide): 実験の中の `inference/` を登録する. 意思決定の既定値は問題の設定の損得と制約
