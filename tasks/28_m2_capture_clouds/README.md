# 28 多視点の撮影から点群を画面の API だけで通す (合成の形)

## 目的

節目「点群と領域を画面で通す」(ROADMAP.md の M2) の確かめのうち, 多視点の撮影から点群 (J7). 27 と同じ通しを, 撮影 (画像, 姿勢, 深度) と正確な点群の組で行い, 段階ごとに OK, 手, 誤りを表にする. 通しの部品は 27 の `pairs.py` (アプリの起動と記録は 25 の `apps.py`) を使う.

- **課題**: 物を周りから撮った撮影から, 物の表面の点群を作る (架空). 空の問題の設定から問いに答える
- **データの分析**: ML-Fathom のファイルの組の書き出し (撮影と点群). 撮影の大きさはそろっているので中身の手順はかけない. 書き出しは 1 件ごとに物の中心を原点にする平行移動をかける (ML-EDA の決まり)
- **モデル**: ML-CreateArchitecture の同梱の例 `point_cloud_predictor`
- **推論で見ること**: ML-Provide の推論の点群が, 正規化の平行移動を戻した元の座標 (撮影の世界の座標) にあるか. 新しい形の正解の点群の重心と比べる

## ディレクトリ構成

```
28_m2_capture_clouds/
├── journey.py   # 合成のデータを作り, 撮影と点群で通す (部品は 27 の pairs.py)
└── README.md
```

作業用の場所の中身は 25 と同じ.

## データ

`journey.py` が作業用の場所に作る. ML-EDA の `write_shape_captures` で, 位置, 大きさ, 色をばらつかせた球と箱 40 個 (中心は原点から ±2 m の範囲), 1 つの撮影 8 枚 (24x32), 正解の点群 2,000 点 (`data/capture_clouds`. 乱数を固定). 推論には, 別の乱数の種で作った新しい形 2 個 (`data/capture_clouds_new`) の撮影を使い, 正解の点群は結果と比べるだけに使う. 用意してもらうデータは無い.

## モデル

ML-CreateArchitecture の同梱の例 `point_cloud_predictor` (入力 512 点から 256 点を出す PointNet の形). 入力の点の数は骨組みの config の `data.input_points` (512) と同じなので, 例のまま使う.

## 学習の設計

27 と同じ. エポックの数は骨組みの既定の 30 (Chamfer 距離の検証は 2 エポックごと. 10 秒ほど). 段階と API も 27 と同じ.

## 気付いたこと

- 同梱の例が骨組みの既定の点の数と同じなので, 出す点の数 (2000) を画面が当てないことは, この課題では手にならない. 例が出す点の数 (256) は正解の点の数と違うが, 骨組みの Chamfer 距離は点の数が違っても求まる
