# 台車の棒を立て続ける

ML-Quest で問題 (`problem.yaml`) から書き出した, ML-Found の学習のプロジェクトの骨組み (Gymnasium の形の環境で方策を学び, 守りと一緒に書き出す).

## 課題から行動まで

- 台車の設備の担当の課題: 台車の上の棒を立て続けるのに, 人が付きっきりで押す
- 今のやり方: 人が棒の傾きを見て左右に押す
- 解けたと言える指標: 人が押す時間 (時間 / 日. 今 8. 目指す 1. 小さいほど良い)
- 方策が各歩の観測を見た時点に台車を押す向きを決める
- 機械学習の受け持ち (効果を見積もる): 押す向きを選ぶ方策
- 方策の守り: 行動の上限 左右に押すだけ. 止める条件 台車が中心から 2.4 を出たら. 外れたら 決めた行動にする (例: 動かさない). その行動 0. 決める人 設備の責任者
- 方策を学ぶ環境: Gymnasium の CartPole-v1
- 要る機能: rl
- 成功の基準: 守り付きの評価で報酬の平均が 195 以上

## 次にすること

学習する環境には ML-Found, Gymnasium (ML-Found の追加の依存 `rl`), ML-ModelControl (`modelcontrol`) を入れる (config の `requires` で足りなければ入れ方を示して止まる). データの分析の段階は無い (行動の結果は環境とのやり取りで集める).

1. **環境**: Gymnasium の `CartPole-v1` (問題の答え. config の `env.id`). 学習用, 検証用, 守り付きの評価用に別々に作る
2. **守り**: config の `guards` に, 問題の守り (文) を観測と行動の空間に合わせた数の並びで書く (行動の上限: 左右に押すだけ. 止める条件: 台車が中心から 2.4 を出たら). 外れたときの動きは `action` (決めた行動にする (例: 動かさない)). 範囲と方策を使ってよいかは 設備の責任者 が決める. 安全の違反は環境が info の `cost` に 0 より大きい値を入れた歩で数える
3. **学習・評価** (ML-Found): `python train.py`. 方策の頭 (観測から行動のスコアか平均) は ML-ModelControl の定義 `models/policy.yaml` (config の `model.spec`) から組み立てる. 1 回目の `python train.py` で, 定義が無ければ観測と行動の空間から既定の定義 (全結合と Tanh を 2 段と, 行動の数の全結合) を書く. 直すなら モデルの作成・選定の段階で開いて同じ場所に保存し, もう一度学習する (既にある定義は書き直さない. 消すと次の学習で既定の定義を書き直す). 定義は入力 (観測) と出力 (行動) を 1 つずつにし, (1, 観測の要素の数) の観測から (1, 行動の数) の出力を出す (違えば学習の前に止まる). 価値の関数は `model.py` の `PolicyNet` (印 TODO). 学習の方法は config の `algorithm` (`auto` は番号で選ぶ行動なら REINFORCE の `ReinforceStep`, 連続の行動なら `ActorCriticStep`). 検証用の `valid/reward` (評価のエピソードの報酬の和の平均. 大きいほど良い) が最も良いモデルを選ぶ. 結果は `outputs/<実験の名前>/<日付>/<時刻>/` に残る (`task.yaml`, 学習の記録)
4. **方策の一式と守り付きの評価** (ML-Inference): 学習の後に, 守りと一緒に実験の中の `policy/` に方策の一式を書き出し, 読み直して守りを当てたまま環境で動かした結果を守る指標の表 `evaluations/guarded_episodes.json` に書く. 一式には方策の頭の重みと定義の写し (`policy/model.yaml`. `policy.json` の `metadata.model.spec`) が入り, ML-Inference の `load_policy(<policy/>)` (推論の段階の画面) がモデルを渡さずに定義から組み立てて読み, 観測から守りを当てた行動を返す. 守りを数にしていない (`metadata` の `guards_set` が false) 一式は, 範囲の守りが入っていない. 実機での実行は道具の外で, 環境での結果は実機での結果と別に確かめる
