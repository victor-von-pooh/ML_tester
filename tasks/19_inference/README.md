# 19 学習したモデルで推論し, 結論を出す (推論の段階)

## 目的

推論の段階 (ML-Inference, ML-Provide) で, 17 と 18 で学習したモデルから推論の一式を作り, 新しいデータを推論して結論を出せることを確かめる. 学習のときと同じ前処理とモデルが再現できているかを, 学習のスクリプトが記録したテスト用の評価と同じ値になるかで確かめる.

- **17 (文の分類)**: 言い方を増やした 48,000 件で学習した部分語の BERT (`natural_subword_scratch_48k`). 学習のスクリプトが前処理の外で並びの先頭に [CLS] (語彙の数 + 1) を足しているので, 一式に `prepend` として書く
- **18 (売上の予測)**: 店ごとの売上の全結合のモデル (`store_sales`). 学習のスクリプトが売上を学習用の平均と標準偏差で変えて学習しているので, 一式に `target_scale` として書く. 汚れた元のデータ (表記のゆれ, 重複, 3 つの書き方の日付) をそのまま推論する

学習はしない. このタスクは ML-Found のプロジェクトではなく, 推論のスクリプト `infer.py` だけを持つ.

## 実行方法

ルートのディレクトリで, `.venv` を有効にして実行する (データと出力の場所はスクリプトの場所から決まるので, 他の場所から実行してもよい). 先に 17 の README の 19 から 21 (言い方を増やした 48,000 件のデータ, 部分語での書き出し, BERT の学習) と, 18 の README の 1 から 3 を実行しておく.

```bash
python tasks/19_inference/infer.py
```

CPU で 15 秒ほど (ラベルの無い 100,000 件の推論を含む). 書き出し先は `--out` で変えられる (タスクのディレクトリからの相対パスか絶対パス. 既定の `outputs` は git の管理外). 作った一式 (`outputs/bundle_reviews`, `outputs/bundle_sales`) は, ML-Provide の「場所で登録」で画面から使える.

### このタスクで見つけて直したこと

- **推論で重複が残り, 過去の値がずれる (ML-EDA #23)**: 最初は 18 のテスト用の期間の誤差が 59,128 円 (8.695 %) で, 学習のときの 59,035 円と合わなかった. 元のデータには重複した行が 150 行あり, 学習では重複を落としてから店ごとに前の行の値をずらすが, 推論の前処理 (`Dataset.transform`) は行を増減する手順を飛ばしていた. そのため重複の後の行の「7 つ前」が 1 日ずれていた. 重複を落としてから推論すると 59,035 円になることで原因を確かめ, ML-EDA で, 推論でも行を落とす手順を前後関係のためにかけ, 入力の行の並びに戻すように直した. 目的の列が途中で欠けた履歴も, 学習のときと同じく分かる行だけで前後関係を作るようにした
- **目的の列と特徴量を同じ手順で変えたレシピ (ML-EDA #22)**: `standardize` の `columns` に目的の列と特徴量を並べると, 推論の前処理が手順を丸ごと飛ばし, 特徴量が変換されないまま推論されていた. ML-Inference のレビューで見つけ, 目的の列だけを除いてかけるように直した (17 と 18 のレシピは当てはまらない)
- **結果の画面で決め方の欄が 2 つ出る (ML-Provide #3)**: 画面で出し直したときに見つけた

### 学習のスクリプトの外でしたことを一式に書く必要

17 と 18 は, どちらも学習のスクリプトが前処理の外で入力か目的の値を変えている (17 は並びの先頭に [CLS], 18 は売上の標準化). レシピとモデルの定義だけからは分からないので, 一式を作る人が `prepend` と `target_scale` に書く必要がある. 書き忘れても, どちらも一式を作れてしまい (見本の推論は形しか確かめない), 誤った予測が黙って出る. 17 で `prepend` を書かずに作ると, テスト用の正解率は 0.9445 ではなく 0.8565 になった ([CLS] の無い並びでも位置の埋め込みに収まるので形の誤りにならない). 18 は標準化した値のまま (平均 0 付近) の予測になる. 学習のスクリプトが自分で一式を作る (`make_bundle` を学習の最後に呼ぶ) か, 問題の設定の段階が前処理の外の変換を持たないようにするのが確かだと考えている
