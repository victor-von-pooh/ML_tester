# 37 値段を変える判断を問題の設定から推論まで通す

## 目的

値段を変える判断の課題 (試しに値段を変えた売れ行きの記録から, 商品ごとに利益が最も大きい値段を選ぶ) を, 問題の設定から推論まで, 5 つの画面のアプリ (ML-Pathfinder, ML-Fathom, ML-CreateArchitecture, ML-Dashboard, ML-Provide) の API だけで, 画面と同じ順に通す. 段階ごとに, 画面だけでできたか (OK), 値や場所を手で写すか打つか (手), 誤りかを表にする.

- **課題**: ML-Pathfinder の見本「解約の引き止め」から作り, 課題, 指標, 決めること, 受け持ちを値段の課題に答え直す (架空). 今のやり方は全ての商品を今の値段のまま売る. 値段は今の値段から 1 割より大きくは変えない
- **受け持ち**: 効果を見積もるで, 方策でなく今ある記録で値段を変えた (`varied: price`). 値段の列 `price`, 売れた数の列 `units`, 原価の列 `unit_cost`, 商品の id の列 `product_id`, 行の id の列 `record_id`, 売れた数の予測に使う列 `category`, `weekday`, `list_price`, 最良を選ぶ指標は売れた数の平均絶対誤差, 判断は値段の候補 (今の値段から -0.1, -0.05, 0, 0.05, 0.1) から変える幅の上限 0.1 の中で選ぶ
- アプリの起動と段階の記録は 25 の `apps.py` を使う

## ディレクトリ構成

```
37_price_change/
├── journey.py   # 合成の売れ行きの記録を作り, 問題の設定から推論まで通す (部品は 25 の apps.py)
└── README.md
```

作業用の場所 (既定は一時ディレクトリ. `--work` で変えられる) に置くものは 25 と同じ.

## データ

`journey.py` が作業用の場所に作る合成の売れ行きの記録 (20 商品 × 500 日の 10,000 行. 乱数を固定). 列は `record_id`, `product_id` (`p00` から `p19`), `category` (偶数の番号の商品は `food`, 奇数は `tool`), `weekday` (0 から 6), `list_price` (商品の今の値段 100 から 300), `price` (今の値段を, 日ごとに無作為に 0.8, 0.9, 1.0, 1.1, 1.2 倍にしたもの), `unit_cost` (今の値段の 6 割), `units` (売れた数), `stock_left` (売れた後に決まる残りの数). 売れた数の平均は 20 × 倍率 ^ 弾力性 (食品は -3.0, 道具は -1.2) で, 週末は 1.3 倍. 原価が今の値段の 6 割なので, 利益が最も大きい値段は食品で今の値段の 0.9 倍, 道具で上限を超えた高い値段になる (弾力性が一定なら, 最も良い値段は原価 × 弾力性 / (1 + 弾力性)). 推論には, 商品ごとに今の値段の 1 行 (別の乱数の種で売れた数も持つ. `sales_now.csv`) を使う. 用意してもらうデータは無い.

## モデル

ML-CreateArchitecture の売れ行きの雛形 `tabular_price` を, データセットの列の数 (`category` のワンホットの 2 列, `weekday`, `list_price`, 値段の列 `price` の 5) に書き換えたもの. 出力は売れた数の予測 1 つ. 雛形は問題の設定から決まり (`POST /api/project/target` の `example`), 幅は `POST /api/templates/adapt` の `features` で書き換える.

## 学習の設計

ML-Pathfinder が書き出した骨組み (`train.py`) を書き換えずに, ML-Dashboard の「学習を起動」で動かす. 骨組みは学習の前に予測の平均を学習用の売れた数の平均に合わせ, 既定の 100 エポック (検証用の誤差が 10 エポック続けて良くならなければ止める) のうち検証用の売れた数の平均絶対誤差 (`valid/mae`) が最も小さいエポックを選び, 検証用とテスト用の売れた数の誤差, 値段の弾力性, 選んだ値段と今の値段の見込みの利益の比べを評価の表 (`evaluations/price_<分割>.json`) に書き, 値段の推論の一式 (版 13) を実験の `inference/` に作る.

## 期待する結果

誤りの段階 0, 手の段階 0. 学習の段では, テスト用の弾力性の平均が負 (値段を上げると売れた数が減る向きを学ぶ). 推論の段では, 選んだ値段は全て変える幅の上限 0.1 の中で, 道具の 10 商品は全て上限まで上げ (+0.1. 合成のデータの真の弾力性 -1.2 からの最も良い値段と同じ), 食品の 10 商品のうち 5 以上の値段を下げる. 合成のデータの真の弾力性 -3.0 からは食品の全てで 1 割下げるのが最も良い. 食品の値段への敏感さを小さく学ぶと 1 つも下げないので, 下げる向きを学んだしるしとして半数を線にし, 商品ごとの推定のばらつきで全てまでは下げないことを許す. 見込みの利益が今の値段以上であることは, 候補に今の値段 (0) があるので必ず成り立ち, 良し悪しの確かめにならない (表の説明に出すだけ). 合成のデータの真の売れた数の平均で数え直した, 今の値段に対する真の利益の比も説明に出す (候補の中で真に最も良い値段なら 1.073).

## 実行方法

25 の README の「実行方法」と同じく, 5 つのアプリをこのリポジトリと同じディレクトリに clone して `make setup` を済ませ, ルートのディレクトリで実行する (`uv` が要る). 手元で動かせなければ, CI の「通しを測る」(`.github/workflows/journeys.yml`) を `tasks` に `37_price_change` を入れて手で起動する.

```bash
.venv/bin/python tasks/37_price_change/journey.py               # 2 分ほど (環境づくりはネットワークを使う)
.venv/bin/python tasks/37_price_change/journey.py --work <作業用の場所> --apps <アプリの親のディレクトリ>
```

- 最後に段階ごとの表と, 手の段階と誤りの段階の数を出す. 誤りがあれば終了の番号は 1
- 学習の環境はプロジェクトの `.venv` に, ML-Found と ML-EDA, ML-ModelControl, ML-Inference を git から入れる (uv の手元のキャッシュがあれば十数秒)

## 気付いたこと

- **売れた数のモデルは既定の 100 エポックの終わりまで良くなり続ける**: 骨組みは学習の前に予測の平均を学習用の売れた数の平均に合わせ, 既定 (AdamW, 学び率 0.001, 100 エポック, バッチ 128) で学ぶ. 検証用の平均絶対誤差は 100 エポック目まで下がり続け, Early Stopping は働かない. モデルの弾力性の平均 (テスト用 -1.93) は記録の要約の -2.14 より絶対値が少し小さく, 食品のうち 3 から 4 商品は値段を下げない. 画面では ML-Dashboard の学習の起動で config の中身 (`config_text`) を変えてエポックを増やせる
- **ML-EDA の値段の要約の `price_confounded` が売れた後に決まる列を拾う**: 値段は無作為に変えているが, 売れた後に決まる列 `stock_left` (40 − 売れた数) は売れた数を通して値段と関わるので, 値段と強く関わる列として出る. 雛形のレシピは同じ列を落とすので学習には響かない. 値段の関わりを見る列から, 売れた数と強く関わる列か問題の設定の除く列を外すと, 偏った値段の記録だけを知らせられる
- 商品ごとに今の値段が違う記録では, 商品を見分ける列が予測に使う列に無いと, 値段の高い商品と安い商品の売れた数の差が値段の効き目に混ざる. `product_id` は予測に使えない (行の id と同じく数えない列) ので, 今の値段 `list_price` を予測に使う列に入れた
- 値段の一式は ML-Provide で問題の設定を使わない (候補と変える幅の上限は ML-Quest が骨組みの config に写し, 骨組みが一式に写す). 学習の後に候補や上限を変えるには, 推論で値段の判断 (`decision` の `candidates` と `max_change`) を渡すか, 問題の設定を直して骨組みを書き出し直す
- 値段を変える判断には見本が無いので, 見本「解約の引き止め」から作って課題と受け持ちを答え直す (ML-Pathfinder の値段を変える判断のテストと同じ作り方). 受け持ちを効果を見積もるにして今ある記録から集めると答え, 変えたものに値段 (`varied: price`) を選ぶと値段の問いが出る
- ML-CreateArchitecture のデータセットの入力は, ML-Fathom が parquet で書き出した表から値段の列の名前まで読み, 保存の注意は出ない (32 と同じ追加の依存 `project` の環境)
